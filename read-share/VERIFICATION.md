Final image: 3,408 bytes text, zero initialized data, 1,664 bytes BSS. Startup, vector table, peripheral code, and linker script are part of the link. This is not MCU execution or flashing.

Enumerated all 4,096 four-operation words over eight tagged acquisition/release operations against an independently expressed ownership oracle, stopping each word at its first illegal event. Additional regressions exercise three concurrent readers, reader leave/rejoin, writer isolation in both directions, duplicate writer, simultaneous strobes, opposite raw endpoint, insufficient tag setup, held strobe, tag chatter, acquisition gap, retained terminal evidence, timestamp wrap, transactional overflow at final release, encoding bounds, and impossible ownership.
- Serial register-model tests passed under UndefinedBehaviorSanitizer: bounds, busy rejection, timeout, recovery, and wrap. Main-loop tests passed: lost boot record, recurring compatibility policy for late attachment, busy transport, timeout diagnostics, and watchdog startup failure before status. Register mapping and board timing are controlled test doubles, not physical measurements.
- `xvfb-run -a python3 -m unittest discover -s read-share/tests -p test_app.py -v`: 15 tests passed with Python 3.13.5. Tests cover ownership and cohort conservation, checksum-valid impossible evidence, unaccounted identity changes, new cohorts, reader reentry, wrong protocol/policy, duplicate freshness, pause freezing, rollback, halted immutability, truncated-frame recovery, partial EOF, replay restrictions, and exclusive mode-0600 export.
- The actual Tk event loop consumed synthetic production-C-encoder records through Linux pseudo-terminals, paced by device timestamps. Ledger, History, and Integrity screens were exercised. Export contents and permissions, duplicate connection refusal, serial hangup, retained origin, and replay replacement were checked. No physical USB connection was exercised.
- `/usr/bin/python3 read-share/tools/generate_hardware.py`: generated native schematic, PCB, project, authored symbol library, connectivity manifest, and XML netlist.
- `/usr/bin/python3 read-share/tools/check_hardware.py`: KiCad 9.0.2 reported zero ERC violations, zero DRC violations, and zero unconnected items. Fresh schematic netlist, saved netlist, PCB pads, values, complete footprint identifiers, and manifest agree on 14 components, 30 pads, and 9 nets.
- Schematic and combined copper/silkscreen SVG exports were rendered with rsvg-convert and visually inspected. Component groups, input labels, ground-only warning, author credit, outline, and routing are present without gross visible overlaps. This is not an assembly or fabrication review.
- `python3 read-share/tools/check_release.py`: README has 3,271 whitespace-delimited words; production C has 569 nonblank, noncomment lines excluding tests and headers. Every authored deliverable contains jayis1 attribution. Required CAD files, attribution, private-key marker scan, and whitespace checks pass. Build outputs and local CAD preference files are ignored.

## Validation path and limitations

Tests were added before the new ownership implementation and initially failed because the required conflict classification and class counters did not exist. App tests initially failed because the new RS1 contract module was absent. Both paths pass after implementation; no test expectation was weakened to hide a production failure. Shared transport and carrier code are disclosed reuse, not newly invented circuitry.

The configured web extractor could not extract manufacturer PDFs. Direct ST UM1724 download failed with an HTTP/2 transport error; an HTTP/1.1 retry timed out. This run therefore does not claim a fresh manufacturer-document verification. The pin/register map is reused from the existing Nucleo platform; current manufacturer manuals, actual board revision, solder bridges, and purchased components must be checked before connection. The missing optional CairoSVG renderer was replaced by installed rsvg-convert. GitHub CLI is not logged in; publication uses the repository's existing Git HTTPS credential helper without reading or changing credentials.

No fabrication, MCU programming, electrical bring-up, waveform acquisition, calibrated timing, watchdog timing measurement, current measurement, brownout test, ESD/EMC qualification, enclosure validation, or deployment occurred. Passive-symbol ERC cannot validate the external power source. A malicious adapter can falsify ownership, and some missed events or observer resets can remain indistinguishable from plausible traffic. This release is an unbuilt diagnostic prototype, not a production lock monitor, enforcement boundary, or certificate of target security.
